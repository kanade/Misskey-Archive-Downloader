# Misskey Archive Downloader

Misskeyのノートとドライブファイルをまとめてダウンロードし、ブラウザで閲覧できる自己完結型アーカイブ（ZIP）を作成するツールです。

## 機能

- **MiAuth認証** — Misskeyインスタンスに安全にログイン
- **ノート取得** — API経由での全件取得、またはMisskeyエクスポートJSONのアップロードに対応
- **お気に入り・クリップ取得** — API / JSONアップロードの両モードをサポート
- **ドライブファイルダウンロード** — 外部インスタンスのファイルも `thumbnailUrl` へのフォールバックで可能な限り取得
- **エラーログ** — ダウンロード失敗ファイルのURL・添付ノートのURLを `error.log` に記録
- **自己完結型ビューア** — ZIPを解凍して `index.html` をブラウザで開くだけで閲覧可能
  - 全文検索、タグ・公開範囲・ローカルのみ／連合あり・メディアフィルター（公開範囲の表示にも「ローカルのみ」を付ける）
  - リアクション・CW・投票・ライトボックス表示
  - クライアントサイドページネーション（30件/ページ）

## 取得方法オプション

| 項目 | API | JSONアップロード |
|------|-----|-----------------|
| ノート | ✅ リアクションも取得 | ✅ Misskeyエクスポート形式 |
| お気に入り | ✅ | ✅ |
| クリップ | ✅ | ✅ |

## キャッシュ

- **ノートキャッシュ（IndexedDB）** — 前回取得分を保持し、差分のみAPIで再取得。オフにすると全件再取得（リアクションの最新化に有効）。
- **ファイルキャッシュ（IndexedDB）** — オプトイン。ダウンロード済みファイルをIndexedDBに保存し、再エクスポート時に再利用。
- **絵文字キャッシュ（IndexedDB）** — 既定でオン。ファイルキャッシュとは別にオン・オフできる。取得した絵文字を URL ごとに保存し、URL が同じ絵文字は取得し直さずに使う（サーバーやユーザーで置き場所を分けないので、管理者アプリでは同じサーバーの別のユーザーの作成でも再利用する。サーバーが違えば URL も違うので取得する）。「キャッシュを削除」はファイルと絵文字の両方を消す。

## ZIPの構造

```
archive.zip
└── misskey-archive-<domain>-<date>/
    ├── index.html        ← ビューア（デザイン・ロジックのみ）
    ├── archive-data.js   ← エクスポート情報と data/ 内スクリプトの一覧（file://でも動作）
    ├── data/             ← ビューアが順に読み込むデータ（notes-001.js 等、一定サイズごとに分割）
    ├── index.json        ← エクスポートメタデータ
    ├── notes.json        ← ノート一覧（localPath付き）
    ├── favorites.json    ← お気に入り（取得時のみ）
    ├── clips.json        ← クリップ（取得時のみ）
    ├── error.log         ← ダウンロードエラー詳細
    ├── error-log.js      ← error.log と同じ内容（ビューアのポップアップ用）
    ├── emojis/           ← ノートの本文・CW・リアクションで使われているサーバーのカスタム絵文字
    └── files/            ← ダウンロード済みドライブファイル
```

サーバーのカスタム絵文字は、アーカイブのノート（返信先・リノート先を含む）で使われているものだけを `emojis/` に保存し、`index.json` の `emojis` をその場所に書き換えます。サーバーやストレージが無くなっても表示できます。他のサーバーの絵文字は元の URL のままです。

`error.log` の「添付ノート」には、アーカイブ内の場所（`index.html#note-<ID>`）と元の URL を書きます。ビューアを `index.html#note-<ID>` で開くと、そのノートを表示します（サーバーが無くなっても開けます）。

ビューアの右下の「error.log」ボタンを押すと、`error.log` の内容をポップアップで表示します。中の `index.html#note-<ID>` を押すとそのノートに移り、URL は新しいタブで開きます（`file://` で開いたビューアは同じフォルダのファイルを直接読めないため、同じ内容を `error-log.js` としても書き出しています）。

### ビューアのみの更新

データ（`archive-data.js` と `data/`）とビューア（`index.html`）は分離されているため、新しい `index.html` を既存アーカイブのものと差し替えるだけでデザインを更新できます（再エクスポート不要）。新しい `index.html` は、配布用のサイトに置いた `index.html.zip` を解凍して入手します。次のリンクはどれもこのファイルをブラウザでダウンロードします（デスクトップ版・管理者アプリでは PC のブラウザが開きます）。

- トップページの「最新ビューア（index.html）」
- エクスポート画面の「最新ビューア（index.html）のみダウンロード」（本ツール・管理者アプリ）

ビューアのテンプレートは `src/lib/viewer-template.ts` の `viewerHtml()` です。`npm run build:viewer` で `dist-viewer/index.html` を作れます（Node.js 22.18 以降）。「Build Desktop App」はビルドのたびにこれを `index.html.zip` にして `latest` リリースに入れます。

## デスクトップアプリ（Tauri）

Windows・macOS向けのネイティブアプリも提供しています。

- **CORSの影響を受けずに画像をダウンロード可能**（RustバックエンドでHTTP取得）
- MiAuth認証をアプリ内の組み込みWebViewで処理（外部ブラウザ不要）
- 開始時にネイティブのダイアログで保存先を選び、ディスクへ直接書き出す（メモリに全体を載せないため大容量アーカイブにも対応）
- 保存形式は「ZIPファイル」と「フォルダ（圧縮しない）」から選べる。フォルダはアーカイブの中身をそのまま書き出すため、解凍せずに `index.html` を開ける
- F12 / Ctrl+Shift+I で DevTools を開閉
- エクスポート画面の右（ウィンドウが狭いときは下）のログ欄に、進捗と、ファイル・絵文字 1 件ごとの取得の成功・失敗（失敗の理由を含む）が処理中に出る（「コピー」「保存」で書き出せる）。出力先の `error.log` には失敗だけが入る

### macOSでの初回起動

アプリはアドホック署名のみで、Appleの公証（notarization）は受けていません。ダウンロードしたアプリを初めて開くと Gatekeeper の警告が出るため、次のいずれかで許可してください。

- 一度開こうとした後、「システム設定」→「プライバシーとセキュリティ」→「このまま開く」
- ターミナルで隔離属性を外す: `xattr -dr com.apple.quarantine "/Applications/Misskey Archive Downloader.app"`

### ビルド

GitHub Actions の「Build Desktop App」を手動で実行すると（`gh workflow run tauri-build.yml` でも可）、ローリングリリース [`latest`](https://github.com/kanade/Misskey-Archive-Downloader/releases/tag/latest) に固定ファイル名でバイナリを公開します。プッシュではビルドしません。

- `Windows-x64.zip`（`misskey-archive-downloader.exe` を ZIP に圧縮したもの）
- `macos-arm64.dmg`
- `macos-x64.dmg`
- `index.html.zip`（差し替え用ビューア。そのビルドのテンプレートから作った `index.html` を ZIP に圧縮したもの）

Webアプリのトップページのダウンロードリンクは、配布用のサイトに置いた同じ名前のファイルを指します。リリースのファイルを配布用のサイトに置くと、トップページからダウンロードできます。

リリースはビルドのたびにタグごと作り直すため、リリースの日付とタグはそのビルドのコミットになります（ダウンロード数は毎回 0 に戻ります）。

## 管理者アプリ（閉鎖したサーバーの代理エクスポート）

閉鎖したサーバーの管理者が、登録していたユーザーの代わりにアーカイブと Misskey 標準のエクスポートを作るための Windows アプリです。本ツールとは別にビルドします。

- サーバーの DB から対象ユーザーのトークン（`user` テーブルの `token` 列）を読み、そのユーザーとしてサーバーの API を呼びます。DB へは読み取りのみです
- 作るもの（1 つの ZIP にまとめます）
  - 本ツールと同じアーカイブ（ノート・お気に入り・クリップ＋添付ファイル＋ビューア）
  - 標準エクスポート（ノート・お気に入り・クリップ・フォロー・ミュート・ブロック・リスト・アンテナ）。ZIP 内の `exports/` に入り、そのまま別のサーバーにインポートできます
- 標準エクスポートの結果は、対象ユーザーのドライブにもファイルとして残ります
- ノート・お気に入り・クリップの標準エクスポートは 24 時間に 1 回しか依頼できません。24 時間以内に依頼済みのときは、その結果を使います

### 事前の準備（サーバー側）

1. Misskey（本体・PostgreSQL・Redis）を、外部に公開しない状態で起動する
2. 外向きの通信を止める場合も、オブジェクトストレージへの書き込みは通るようにする（設定ファイルの `proxyBypassHosts` にエンドポイントのホスト名を入れる、またはコントロールパネルでオブジェクトストレージのプロキシ利用をオフにする）。通らないと標準エクスポートが失敗します
3. 対象ユーザーが凍結されている場合は、実行する間だけ解除する
4. アプリを使う PC から Misskey と PostgreSQL に接続できるようにする。PostgreSQL は既定ではサーバー自身からの接続しか受け付けないため、次のどちらかにする
   - アプリの「SSH のポート転送を使う」をオンにする（PC からサーバーへ SSH で接続できればよく、サーバー側の設定は変えずに済む）
   - `listen_addresses` と `pg_hba.conf` で PC からの接続を許可する

### 使い方

1. 接続先を入れる。パスワード以外は保存されます
   - SSH のポート転送を使う場合は、SSH の接続先（例: `user@server`）とポートを入れる。アプリが PC の `ssh` コマンドを起動し、Misskey と PostgreSQL へのポート転送を行います。鍵・ssh-agent・`~/.ssh/config` はそのまま使えます。パスワードの入力や確認の質問には答えられないため、鍵などで入力なしに接続できるようにしておきます（初めて接続するサーバーのホスト鍵は自動で登録します）
   - Misskey の URL と PostgreSQL のホスト・ポート・データベース・ユーザー・パスワード。SSH を使う場合、Misskey の URL と PostgreSQL のホストはサーバーから見た場所（例: `http://127.0.0.1:3000`、`127.0.0.1`）です
2. 必要なら「URL の置き換え」を入れる。ファイルの URL が、もう配信していないドメインを指している場合に使います（例: `https://example.com/media/ https://<ストレージのURL>/<バケット>/`）。サーバーの URL の `/files/`（Misskey が配信）と `/proxy/`（元の URL を直接取得）は自動で処理します
   - 閉鎖したサーバーのドメインが 410 を返す Cloudflare Workers の後ろにある場合は、「X-Gone-Bypass-Token ヘッダを付ける」をオンにして、トークンと、ヘッダを付けるドメイン（1 行に 1 つ）を入れる。書いたドメインとそのサブドメインへの HTTP 通信（Misskey の API と、ファイル・絵文字・標準エクスポートの取得）にだけ `X-Gone-Bypass-Token: <トークン>` を付けます（SSH と PostgreSQL には付きません）。トークンとドメインはほかの接続先と同じく保存され、トークンはログには出ません
3. 対象のユーザー名を入れて「確認」
4. 作るものを選んで「作成する」。保存先を選ぶと処理が始まります
   - アーカイブのノート・お気に入り・クリップは、それぞれ元データを選べます。「API」はリアクションやリノート先まで取得します。「標準エクスポート」はこのあと依頼する標準エクスポートの結果を、「JSON ファイル」は手元の標準エクスポートのファイルを使います（どちらもリアクションは含みません）
   - 保存形式（ZIP／フォルダ）、ノートとドライブファイルのキャッシュ、ビューアだけのダウンロード、テーマの切り替えは本ツールと同じです

画面の右（ウィンドウが狭いときは下）のログ欄に、DB の検索、API の送信（トークンは除く）、標準エクスポートの状態、ファイル・絵文字 1 件ごとの取得の成功・失敗などがすべて出ます。エラーは原因まで含めた全文です。「コピー」「保存」で書き出せます。出力先の `error.log` には失敗だけが入ります。

## 注意事項

- データはすべてブラウザ（またはデスクトップアプリ）内で処理され、外部サーバーには送信されません。
- 認証トークンはブラウザのローカルストレージに保存されます。
- ノート数・ファイル数が多い場合、処理に時間がかかります。
- ビューアの閲覧には `index.html` をローカルHTTPサーバー経由で開くか、ローカルファイルアクセスを許可したブラウザが必要です（`npx serve` 等）。
